# 신조(Sinjo)

신조어(新造語) 사전·번역·퀴즈 서비스. 최신 신조어를 검색하고, AI로 번역·해설을 받고, 퀴즈로 익히고, 활동을 기록하며 포인트로 보상받는 웹 서비스입니다.

## 기술 스택

**백엔드**
- Spring Boot 4.1 (Java 21), Spring Security (JWT 인증), Spring Data JPA
- PostgreSQL + pgvector (임베딩 검색)
- Spring AI (OpenAI ChatClient) — AI 번역/챗봇/학습 콘텐츠 생성
- Apache POI — 엑셀 업로드/다운로드
- JWT(jjwt), Spring Mail(비밀번호 재설정 메일)

**프론트엔드**
- React 19 + Vite
- React Router 7
- axios, react-icons, xlsx

## 주요 기능 (main 병합 기준)

### 인증 · 계정
- 이메일/비밀번호 회원가입·로그인 (JWT, 24시간 유지)
- 비밀번호 재설정(이메일 발송 → 토큰 확인)
- 네이버 소셜 로그인
- 구글 로그인 버튼은 UI만 있고 아직 "준비 중" 안내만 뜸 (미구현)

### 신조어 사전
- 검색 / 카테고리 / 초성 / 연도 / 정렬 필터링, 페이지네이션
- 단어 상세 페이지, 좋아요, 즐겨찾기
- 인기 랭킹, 오늘의 신조어
- 검색 결과 엑셀 다운로드 (조건별 필드 선택)

### AI 번역 · 챗봇
- 실시간 신조어 → 표준어 번역 (AI 해설 포함)
- 마이크 음성 입력(STT, Whisper API) — 텍스트 입력창에 채워주기만 하고 자동 번역은 하지 않음
- 챗봇 대화형 번역, AI 학습 모드(오늘의 학습 콘텐츠, 완료 처리)

### 퀴즈 · 게임
- 객관식 / 초성 / 주관식 3종 게임
- 재도전 시 문제 재조회, 오프라인(네트워크 실패) 시 폴백 채점
- 게임 결과 저장 및 마이페이지 게임 기록 연동

### 마이페이지
- 프로필(닉네임/비밀번호 변경), 최근 번역 기록(상세 모달, 즐겨찾기 토글)
- 즐겨찾기 단어 목록, 게임 기록
- 활동 통계 — 출석 캘린더, 월간 출석률, 활동 달성도
- 배지 & 포인트 — 단어 번역/게임 플레이 달성도 배지, 보유 포인트
  - "게시판 이용" 배지는 게시판 기능이 아직 없어 프론트 전용 프로토타입 상태
- 이번 주 출석 기록

### 포인트 시스템
- 적립: 신규 번역 저장(같은 문장 재저장은 적립 안 됨, 어뷰징 방지), 퀴즈 정답 수만큼
- 포인트 상점: 관리자가 등록한 상품을 포인트로 구매 (서버가 가격을 최종 검증해 클라이언트 조작 방지)
- 잔액은 거래 내역(ledger) 합산 방식이라 잔액-내역 불일치가 생기지 않음

### 관리자
- 대시보드(회원/단어/퀴즈 수 요약)
- 용어 관리 (등록/수정/삭제, 엑셀 일괄 업로드)
- 퀴즈 관리 (등록/수정/삭제, 사전 연동으로 신조어·뜻 자동 채우기, 오답 보기 최소 개수 검증)
- 회원 관리 (권한 부여/해제, 닉네임 수정, 삭제)
- 포인트 상점 관리 (상품 등록/수정/삭제, 가격 즉시 반영)
- 표 형태 화면은 이름 클릭 시 바로 수정되는 인라인 편집 방식

## 프로젝트 구조

두 프로젝트가 한 레포에 있고 빌드/실행 도구를 공유하지 않습니다.

```
back_end/    Spring Boot REST API (com.slangs.sinjo)
  controller / service / repository / entity / dto / security / config
front_end/   React SPA
  pages/         라우트별 화면
  components/    재사용 컴포넌트 (MyPage, Header, Footer, auth, guards)
  api/           도메인별 API 클라이언트 (client.js 를 통해서만 fetch)
  css/           화면·컴포넌트 단위로 분리된 스타일시트
```

## 실행 방법

**백엔드** (`back_end/`, PostgreSQL 필요)
```
./gradlew bootRun          # Windows는 gradlew.bat
```
`DB_USERNAME`, `DB_PASSWORD`, `JWT_SECRET`(32바이트 이상), 관리자 계정 정보를 환경 변수로 설정해야 합니다. 자세한 내용은 `CLAUDE.md` 참고.

**프론트엔드** (`front_end/`)
```
npm run dev                # :5555
```
`.env`에 `VITE_API_BASE_URL` 필요.

## 알려진 이슈

- `Word.category`: 컬럼은 있지만 값을 채우는 코드가 없어 항상 null
- 좋아요 중복 방지 없음 — 같은 사람이 여러 번 누를 수 있음
- refresh token 없음 — access token 24시간 만료 후 재로그인 필요
- 권한(role) 변경은 재로그인 전까지 토큰에 반영 안 됨

## 앞으로 구현 예정

- 게시판 기능 (지금은 마이페이지 배지에 자리만 마련된 프로토타입)
- 구글 소셜 로그인 연동
- 좋아요 중복 방지, refresh token 도입
- `Word.category` 실제 값 채우기
- 포인트 상점 아이템 다양화 — 닉네임 뱃지·아바타 이모지·닉네임 색상·칭호 등 실제 프로필에 반영되는 코스메틱 아이템 (현재 4개 상품은 관리자가 등록/수정/삭제만 가능하고, 구매 후 프로필에 실제로 표시되는 로직은 아직 없음)
- 소모성 아이템(출석 프리즈권, 퀴즈 힌트 공개권 등) — 지금 포인트 모델은 "구매하면 계속 보유"만 지원해 별도 설계 필요
